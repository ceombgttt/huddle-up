=== 2. EMAIL VERIFICATION ===

Verify user emails to reduce fake accounts and enable email marketing.

SIGNUP FLOW UPDATE:

CURRENT:
1. User creates account
2. Logged in immediately

NEW:
1. User creates account
2. Account created BUT email unverified
3. Send verification email immediately
4. User can browse but limited features until verified
5. User clicks link in email
6. Email verified ✓
7. Full access granted

VERIFICATION EMAIL:

FROM: Huddle Up <noreply@huddleupus.com>
SUBJECT: "Verify your Huddle Up account 🔥"

BODY (HTML):
"
[Huddle Up Logo]

Hey [Name]!

Welcome to Huddle Up! You're one step away from finding your crew and watching the game.

[Verify Email] (big blue button)

This link expires in 24 hours.

Can't see the button? Copy and paste:
https://huddleupus.com/verify?token=abc123

Questions? Hit reply or email contact@huddleupus.com

See you at the game!
- The Huddle Up Team

[Footer: © 2025 Huddle Up | Privacy | Unsubscribe]
"

VERIFICATION LINK:

URL FORMAT:
https://huddleupus.com/verify?token=abc123def456&email=user@email.com

TOKEN:
- Generate unique 32-character token
- Store in database with email and expiration (24 hours)
- One-time use only

VERIFICATION PAGE:

When user clicks link:

SUCCESS:
"✅ Email Verified!
Your account is now fully activated.
[Continue to Huddle Up] button"

ALREADY VERIFIED:
"✅ Email Already Verified
You're all set!
[Go to Home] button"

EXPIRED:
"⏰ Verification Link Expired
This link is no longer valid.
[Resend Verification Email] button"

INVALID:
"❌ Invalid Verification Link
This link is not recognized.
[Contact Support] button"

UNVERIFIED STATE:

Show banner at top of app:
"⚠️ Please verify your email to unlock all features
[Resend Email] button"

LIMITATIONS WHILE UNVERIFIED:
- Can browse parties (view only)
- CANNOT join parties
- CANNOT create parties
- CANNOT check in
- CANNOT make predictions
- CANNOT enter raffles
- Can view leaderboards
- Can edit profile

RESEND VERIFICATION:

Button available:
- On banner
- In profile settings
- On verification expired page

RATE LIMITING:
- Max 1 verification email per hour
- Prevent spam

ADMIN VIEW:

Admin can:
- See verified vs unverified users
- Manually verify email (if needed)
- View verification rate
- Resend verification on behalf of user

=== 3. PASSWORD RESET FLOW ===

Users need to reset forgotten passwords.

LOGIN PAGE UPDATE:

Add link below password field:
"Forgot password?" (small, blue)

FORGOT PASSWORD PAGE:

TITLE: "Reset Your Password"

FORM:
- Email input field
- [Send Reset Link] button
- "Remember it? [Log in]" link

VALIDATION:
- Require valid email format
- Check if email exists in database

EMAIL EXISTS:
Send reset email
Show: "✅ Reset link sent! Check your email."

EMAIL DOESN'T EXIST:
For security, still show success message (don't reveal if email exists)
Show: "✅ If that email exists, we sent a reset link."

PASSWORD RESET EMAIL:

FROM: Huddle Up <noreply@huddleupus.com>
SUBJECT: "Reset your Huddle Up password"

BODY:
"
[Huddle Up Logo]

Hey!

We received a request to reset your password.

[Reset Password] (big button)

This link expires in 1 hour.

Didn't request this? Ignore this email - your password won't change.

Can't see the button? Copy and paste:
https://huddleupus.com/reset-password?token=xyz789

- Huddle Up Team
"

RESET LINK:

URL FORMAT:
https://huddleupus.com/reset-password?token=xyz789abc

TOKEN:
- Generate unique token
- Store with user ID and expiration (1 hour)
- One-time use

RESET PASSWORD PAGE:

VALID TOKEN:
Show form:
- New password field
- Confirm password field
- Password strength indicator
- [Update Password] button

REQUIREMENTS:
- Minimum 8 characters
- At least one letter
- At least one number
- Passwords must match

SUCCESS:
"✅ Password Updated!
You can now log in with your new password.
[Log In] button"

EXPIRED TOKEN:
"⏰ Reset Link Expired
This link is no longer valid.
[Request New Link] button"

INVALID TOKEN:
"❌ Invalid Reset Link
[Request New Link] button"

SECURITY:
- Hash passwords (bcrypt)
- Invalidate old sessions on password change
- Log password reset events
- Rate limit reset requests (max 3 per hour)

=== 5. DEEP LINKING (OPEN SPECIFIC CONTENT) ===

Links should open specific content in app.

URL STRUCTURE:

PARTY LINKS:
https://huddleupus.com/party/12345
→ Opens party #12345

USER PROFILES:
https://huddleupus.com/user/johndoe
OR
https://huddleupus.com/@johndoe
→ Opens John Doe's profile

VENUE PAGES:
https://huddleupus.com/venue/roccos-tacos
→ Opens Rocco's Tacos venue page

RAFFLE PAGES:
https://huddleupus.com/raffle/weekly-100
→ Opens specific raffle

SPORT PAGES:
https://huddleupus.com/nhl
→ Opens NHL parties only

TEAM PAGES:
https://huddleupus.com/team/panthers
→ Opens all Panthers parties

BEHAVIOR:

IF USER HAS APP INSTALLED:
- Link opens in installed app (not browser)
- Direct to specific content

IF USER DOESN'T HAVE APP:
- Link opens in mobile web browser
- Shows content
- Shows install prompt at top

IMPLEMENTATION:

For iOS (Universal Links):
- Create apple-app-site-association file
- Host at: https://huddleupus.com/.well-known/apple-app-site-association
- Configure associated domains

For Android (App Links):
- Create assetlinks.json file
- Host at: https://huddleupus.com/.well-known/assetlinks.json
- Configure intent filters

ROUTE HANDLING:

App must handle all these routes:
- /party/:id
- /user/:username
- /@:username
- /venue/:slug
- /raffle/:slug
- /:sport (nfl, nba, nhl, etc.)
- /team/:team-name

404 HANDLING:

If content not found:
"Oops! This party was deleted or doesn't exist.
[Browse All Parties] button"

SHARE DETECTION:

When user arrives via deep link:
- Track referrer
- Award points to sharer (if applicable)
- Show welcome message (if new user)
